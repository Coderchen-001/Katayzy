Mechanical duplicate check: `python tools/ui2/check_inventory_duplicates.py`.
It fails on duplicate IDs, duplicate `path+action`, and empty required fields.

Surface inventory: `python tools/ui2/inventory_ui_surfaces.py`.
It scans all GUI classes for frame/dialog/popup/custom-paint signals and records hard-coded style
counts (`new Color`, `new Font`, `setFont`, `setBorder`, `setOpaque`, `setBackground`,
`setForeground`) plus a P0/P1/P2 priority. A surface may be `保留/不可见/待替换`; it must be
explicitly classified before rendering replacement starts.

Surface coverage: `python tools/ui2/check_surface_coverage.py`.
It joins feature-inventory dialog references to surface classes and lists descriptive names that
need manual mapping in `surface-coverage.md`.

## Status

`feature-inventory.csv` is a **draft** generated from the current `Menu.java`,
`BottomToolbar.java` and right-click menus. Current draft: **255 semantic rows**
(217 menu, 15 toolbar, 17 context, 2 status, 4 dialog). It is not yet complete.

Before the vertical slice is accepted:

1. Review every top-level menu and submenu against the current build.
2. Cross-check against upstream `D:\temp\lizzieyzy`.
3. Add missing keyboard shortcuts and dynamic states.
4. Mark each row `未接 -> 已接 -> 截图通过 -> 交互通过`.

The authoritative label source is `l10n/DisplayStrings_zh_CN.properties`, not Java string
literals. `menu-label-audit.csv` is generated by `tools/ui2/extract_ui_labels.py` and resolves
`\uXXXX` escapes; use it when checking a label, but do not treat its 2600+ rows as the feature
inventory (it also contains dialog copy and error text).

The inventory has a `source` column with the owning file (for example `Menu.java` or
`RightClickMenu*.java`). It is a coarse source hint, not yet a line number; line-level source is
available in `menu-label-audit.csv` and should be filled into the inventory during Gate 1 review.

The CSV deliberately uses one row per semantic action. Dynamic menu items are expressed through
`state_matrix` and `checked_condition` instead of duplicate rows. Known gaps after the first review:
engine menu variants, game submenu variants, save/clipboard shortcuts, board transforms, edit/branch
navigation, submenu children, data recovery and some special tools. These are being filled in before
Gate 1 can pass.
